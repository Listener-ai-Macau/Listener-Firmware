# Firmware Feature Map

This document is the human-readable companion to `tools/ai/repo_features.ps1`.
The script prints a machine-readable product capability snapshot; this file
explains the same capabilities with concrete source locations.

## Implemented Product Surface

| Feature | What exists | Main paths |
| --- | --- | --- |
| V2 board profile | Active firmware defaults to `ESP32-S3-WROOM-1-N16R8`, 16 MB flash, 8 MB Octal PSRAM, V2 pin map, OTA slots, and diag_log partition layout. Latest hardware maps `PWR_HOLD` to GPIO9 and `BAT_V_ADC` to GPIO10; TPS63020/SY7088 current-sense chips are not populated and must report `GPIO_NUM_NC`. | `ports/esp32/board_pins/Kconfig.projbuild`, `sdkconfig.defaults.esp32s3`, `partitions.csv`, `ports/esp32/board_pins/`, `tools/verify_v2_board_profile_static.ps1` |
| Custom BLE HID fallback keys | Logical custom keys emit stable `KEY1`/`KEY2`/`KEY3`/`KEY4` firmware events. Current V2 GPIO38/GPIO39/GPIO40/GPIO41 fall back to safe non-text BLE HID gestures: single-click F13-F16, double-click F17-F20, and long-press F21-F24 until Listener-Type consumes custom key actions. F13-F24 is the supported bare function-key fallback range; do not allocate F25 or above for product controls because host HID/hotkey handling beyond F24 is not part of the contract. Recording is a configurable Listener-Type custom-key action; `~KEY:KEY3:SINGLE` is a diagnostic-only generated press/release that feeds the same custom-key timing path for automated A1/A2 evidence, and `~KEY:PENDING:KEY1:SINGLE` is a diagnostic-only pending-transport self-test for the first-press wake-and-run HID queue. | `components/keyboard/`, `components/hid_keyboard/`, `ports/esp32/ble_hid*`, `ports/esp32/board_pins/` |
| EC11 push key | EC11 push/GPIO18 is the power-on key while off. In normal active operation, a confirmed single click sends the safe EC11 custom-key fallback `Shift+F13` after the shared double-click window. In `CONNECTED_IDLE` with Type fast recording armed, the first physical edge dispatches recording control within 50 ms; a second short press in that same gesture window is consumed, so it cannot stop recording, emit fallback HID, or start pairing recovery. If the device boots while EC11/GPIO18 is already held, that startup hold is suppressed until a stable release, so the power-on press cannot become a runtime single click, recording trigger, or BLE recovery gesture. This modifier combination is the reserved EC11 runtime custom-key entry and intentionally avoids both the KEY1-KEY4 bare F13-F24 slots and unsupported F25+ keys. `~KEY:EC11:SINGLE` is a diagnostic-only generated press/release for that runtime EC11 custom-key path; `~KEY:EC11:DOUBLE` generates the same non-idle EC11 sampling path for BLE recovery validation. | `ports/esp32/voice_key_input/`, `components/hid_keyboard/`, `ports/esp32/ble_hid*` |
| Recovery | Outside the fast-idle recording gesture, EC11 push double-click recovery and serial `VREC:RECOVERY`, `VREC:RESET`, or `VREC:FORGET` clear pairing/session state. If recovery is requested during an active recording session, the recording FSM cancels that session before reopening pairing. USB `VREC:` commands remain available only for low-level recovery/diagnostics and are not A1/A2 acceptance evidence. | `ports/esp32/voice_key_input/`, `components/voice_recording_control/`, `ports/esp32/ble_hid*` |
| BLE audio transport | VKA1-style 16 kHz microphone sessions are framed as start/audio/stop/cancel/error notifications for Listener-Type. The active N16R8 validation build captures SPH0655 PDM audio through ESP-IDF PDM2PCM, with executable transport invariants for epoch filtering, replay, queue/pool backpressure, stale GATT events, and terminal ownership. | `ports/esp32/audio_capture*`, `ports/esp32/ble_audio_stream*`, `tools/verify_ble_audio_transport_model.py` |
| Diagnostics | `diag_log` records boot, BLE HID/GAP, OTA, health, power, board, status LED, self-test, WARN, and ERROR events by default in flash-backed logs that survive reboot. High-rate INFO sources are runtime-controlled with `~DIAGLOG:ENABLE <source>` / `~DIAGLOG:DISABLE <source>`. The default-off `~DIAGLOG:INPUTDBG:ON/OFF/STATUS` mode is for hardware bring-up and can temporarily persist KEY1-KEY4 raw/stable transitions, EC11 encoder dispatch traces, and EC11 push raw/stable states. Status LED flash diagnostics persist compressed PWR/BLE/OK/WARN active flags, PWR RGB/color class, output-disabled/low-power transitions, and LED-side power/charge/full flags so unplugged no-serial behavior can be reconstructed after cold boot. AI bundles include `summary.param_highlights` for first-pass triage while retaining raw event refs. | `components/diag_log/`, `ports/esp32/diag_log_platform/`, `tools/dump_diag_log.ps1`, `tools/collect_ai_diagnostics.ps1`, `components/status_led/`, `components/keyboard/`, `ports/esp32/voice_key_input/` |
| System health | Runtime heartbeat and resource checks cover heap, BLE state, disconnect conditions, and task health evidence. | `components/system_health/`, `ports/esp32/system_health_platform/` |
| POST and degraded boot | Startup checks report NVS, heap, SPIRAM assumptions, BLE/audio pending state, and degraded boot status. | `main/`, `components/self_test/` |
| Battery and factory readiness | Battery ADC status uses the protected product range `2850mV=0%` and `4150mV=100%`, with `2700mV` reserved as an absolute danger marker. The GPIO10 battery divider reconstructs VBAT from the ESP-IDF calibrated ADC pad voltage plus an NVS-persisted DMM trim set by `~BATTERY:CAL:DMM <mV>`; diagnostics report driver pad mV, trim mV, final ADC pad mV, VBAT, and level. BLE HID Battery Service reports the live ADC-derived level, periodically refreshes the host value, forces a final pre-disconnect battery refresh before hardware shutdown, and clamps to `100%` only when charge power is present and the charger full pin is asserted. USB serial text commands, readiness flags, capability strings, and a verifiable factory firmware package are exposed for production bring-up. | `components/battery_monitor/`, `ports/esp32/ble_hid*`, `ports/esp32/board_pins/`, `tools/package_factory_firmware.ps1`, `tools/verify_factory_firmware_package.ps1`, `tools/verify_ble_battery_service_static.ps1`, `docs/features/factory_firmware_readiness.md` |
| Device settings | `device_settings` persists Type-facing board settings: plugged brightness, battery brightness, per-zone LED brightness caps, plugged/battery low-power idle timeouts, plugged low-power enable switch, plugged/battery auto-shutdown timeouts, knob rotation, and BLE name. If there is no `device` NVS namespace or no saved keys, firmware first applies fresh-device defaults from the shared product macros, reports `loaded_from_nvs=0` for that boot, and writes the same default snapshot into NVS: neutral legacy brightness 100%, status/key LED brightness 50%/80%, EC11/edge brightness 100%, plugged low-power enabled after 3 minutes, battery low-power after 1 minute, and BLE name `listener`. User/NVS settings override those defaults. Normal OTA and tools/flash.ps1 preserve the device-settings NVS namespace; only explicit reset/erase paths such as `~DEVICE:RESET`, factory erase, or erase-flash are allowed to clear it. | `components/device_settings/`, `protocols/listener_device/`, `components/status_led/`, `components/power_manager/`, `tools/verify_device_settings_static.ps1` |
| Low power | GPIO7 USB_DET is disabled/high-Z and is diagnostics-only. Computer USB is inferred from USB Serial/JTAG SOF, so release defaults keep USB Serial/JTAG awake while connected to keep plugged detection, serial diagnostics, and flashing stable; the opt-in `sdkconfig.defaults.usb-light-sleep-debug` profile is bench-only. Charger/external-power state comes from active-low `BAT_CHG/GPIO14` and `BAT_STD/GPIO21` with debounce and near-full guards. `power_manager` preserves connected/disconnected idle power reduction through device-settings thresholds, lets plugged idle stay active when plugged low-power is disabled, keeps idle microphone/I2S sleep independent from external power, keeps restrained PWR visible and reconnecting/connected/TYPE_READY BLE dark in idle, keeps quiet ACTIVE pairing/reconnecting as blue pulses with a dark off phase, keeps HID-only connected visible with a low-floor blue pulse, keeps active disconnected/no-host dark, keeps active `TYPE_READY` steady with a 30 second LED hold for short heartbeat jitter, sends status clear/PWR-only LED frames with the status strip forced to non-DMA before immediately suspending LED transports in low-power idle, arms BAT_CHG/BAT_STD wake only while battery idle, keeps KEY1-KEY4 and EC11 push button-wakeable through edge IRQs plus active-low GPIO light-sleep wake, keeps active-mode KEY1-KEY4 on a 10 ms scan with immediate local white raw preview plus stable LED/HID confirmation behind a 20 ms elapsed-time debounce path so four-key cycling is not sampling-phase dependent and raw edge noise cannot synthesize clicks, keeps EC11 press feedback lower priority than recording/processing/OTA/re-pair effects, and uses the active plugged/battery shutdown timeouts. Real power-off still goes through `PWR_HOLD/GPIO9` drive-high with bounded readback/removal windows and hardware validation evidence; a successful shutdown request also persists the final reason, idle time, blockers, battery snapshot, and power-source flags to NVS before driving `PWR_HOLD/GPIO9` HIGH, so the next boot can report the prior shutdown even if the serial log ended during power removal. | `components/power_manager/`, `components/device_settings/`, `components/status_led/`, `components/keyboard/`, `ports/esp32/voice_key_input/`, `docs/features/low_power_wake_policy.md`, `tools/with_auto_shutdown_guard.ps1`, `tools/verify_power_manager_static.py`, `tools/verify_charging_awake_policy_static.ps1`, `tools/verify_device_settings_static.ps1`, `tools/verify_diagnostic_log_coverage.ps1` |

## Diagnostic Source Controls

`~DIAGLOG:SOURCES` reports every source with `info_enabled`, `info_default`, and the active mask. `~DIAGLOG:ENABLE <source>` and `~DIAGLOG:DISABLE <source>` toggle INFO retention without reflashing; WARN and ERROR events always pass the mask. `~DIAGLOG:LAST:N` emits a bounded recent tail, and `~DIAGLOG:LAST:N:<source>` emits a bounded recent tail for one source.

Default INFO-on sources are `system`, `self_test`, `ble_hid`, `ble_gap`, `ota`, `health`, `power`, `board`, and `status_led`. Default INFO-off high-rate sources are `keyboard`, `voice_key`, `audio`, `voice_rec`, and `ble_audio`.

Normal AI diagnostic collection uses `tools/collect_ai_diagnostics.ps1` or bounded `tools/dump_diag_log.ps1 -Count N`. Full retained export is still available only as the explicit `tools/dump_diag_log.ps1 -Full` path for exceptional manual use.

`diag_log_ai_bundle.json` includes `summary.param_highlights` so AI triage can inspect key BLE GAP connection/subscription params, BLE audio notify/backpressure/replay state, audio or voice recording reject reasons, power shutdown/external-power state, board rail/profile values, and keyboard or voice-key input counts without reading the whole event list. Highlights are enough for first-pass triage when the needed section is present and each finding can cite its `event_ref`. Use raw `events[*]` when checking complete timelines, fields outside the highlighted sections, unknown schema behavior, or missing expected signals. A1/A2 product acceptance is a button/capsule/session timing gate and must include generated KEY3 custom-key recording evidence; ASR accuracy is recorded there but gated separately by A3.

## Boundaries

- Desktop ASR, text polish, insertion, settings, and user-facing BLE status live in `Listener-Type`.
- Industrial design, CAD, enclosure, renders, and manufacturing mechanical constraints live in `voice-keyboard-design`.
- Planning, review state, and cross-repo orchestration are external to this
  product repository.
