# 方案目录说明

这个目录用于存放按步骤推进的开发方案和重要问题修复方案。

## 作用

仓库里的重要任务，在开始实现前，应该先在这里写方案。

方案的用途包括：

- 明确范围
- 把工作拆成有顺序的步骤
- 为每一步定义验收方式
- 设定人工审批检查点
- 避免 AI 一次性跨多步自由发挥
- 只承载当前有效任务，而不是长期堆积历史完成记录

## 使用规则

- 文件名使用 `snake_case`
- 一个文件只对应一个主要任务
- 同一个任务持续更新同一个文件，不要把过程拆散到多个地方
- 文档内要清楚标记每一步状态
- 如果任务范围发生变化，应先更新方案，再继续实施
- 任务完成并且已经整理成功能总结后，应优先删除对应方案文件
- 已完成的稳定知识应转写到 `docs/features/` 或其他稳定 `docs/` 文档中

## 目录清理原则

- 这里优先保留“模板 + 当前有效方案”
- 不建议长期保留已经完成的历史方案
- 如果某个方案已经完成，并且相关知识已经沉淀到 `docs/features/`，则应删除该方案文件

## 建议文件命名

- `feature_name_plan.md`
- `subsystem_bugfix_plan.md`
- `bringup_topic_plan.md`

## 最少应包含的内容

- 标题
- 目标或问题说明
- 范围
- 不在范围内的内容
- 前提与依赖
- 按顺序排列的步骤
- 每一步的验收方式
- 当前阻塞项
