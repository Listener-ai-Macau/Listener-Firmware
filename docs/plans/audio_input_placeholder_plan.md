# 语音输入占位链路方案

## 目标

在当前没有后端、没有语音识别服务接入的前提下，先把这块 `ESP32-S3` 板子的“音频输入 -> 本地触发 -> 输出到 Windows”链路打通。

当前阶段不追求真实语音识别结果，只要求：

- 板子能采到音频输入或等价的音频活动信号
- 固件能基于该输入触发一个固定测试字符串
- 固定测试字符串能通过当前 BLE HID 链路输出到 Windows 主机

也就是说，当前要先验证的是“语音输入入口是否能带动整机交互链路”，不是“语音识别算法是否正确”。

## 当前问题

现在仓库已经完成了 BLE HID 键盘验证链路，能够稳定把脚本注入的字符输出到 Windows。

但音频输入链路还没有开始：

- 仓库里还没有可运行的音频采集驱动实现
- 还没有把板上的音频硬件连到 `ESP32-S3` 固件
- 还没有“音频输入触发固定测试字符串输出”的占位验证路径

所以当前下一步的关键，不是接后端，也不是做语音识别，而是先确认板上音频输入硬件、把最小可用采集链路打通，再复用已经完成的 BLE HID 输出路径。

## 范围

- 识别当前板上音频输入相关硬件与 `ESP32-S3` 的连接关系
- 在仓库内补最小音频采集占位实现
- 定义一个不依赖后端的本地触发条件
- 触发后输出固定测试字符串到 Windows 主机
- 建立一套可重复执行的验证方式

## 不在本次范围内

- 接入任何云端或本地语音识别后端
- 设计正式语音协议
- 做唤醒词、降噪、VAD 优化
- 做产品级音频质量调优
- 扩展与当前占位验证无关的 UI 或业务逻辑

- 当前主机已可连接 `Listener Keyboard`

## 步骤

### 第一步：确认音频输入硬件路径与当前可行的最小占位策略

状态：`completed`

工作内容：

- 继续从原理图确认：
- `MIC` 是否经过 `ES8311` 进入 `ESP32-S3`
- `I2S` 与 `I2C` 控制线的连接关系
- 当前仓库是否已有可复用的音频目录骨架
- 在“真正采样 PCM”与“先做更轻量的音频活动占位检测”之间，选当前最稳的一条路径

本步目标结论：

- 明确当前音频输入硬件链路
- 明确本次占位验证到底采用哪种最小路径
- 明确这个选择是否符合当前仓库的平台边界规则

本步执行结论：

- 当前可以高置信度判断的音频输入硬件路径是：
  `MIC -> ES8311 -> I2S -> ESP32-S3`
- 从原理图文本可确认：
  - 板上 `MIC` 经过 `MIC_P / MIC_N` 差分信号进入音频页
  - 板上存在 `ES8311`
  - `ES8311` 侧存在 `I2S_MCLK`、`I2S_SCLK`、`I2S_LRCK`、`I2S_ASDOUT`、`I2S_DSDIN`
  - `ES8311` 控制总线使用 `SDA1 / SCL1`
- 因此当前最合理的判断是：
  - `MIC` 不是直接进 `ESP32-S3` 的 ADC
  - 而是先进入 `ES8311`，再由 `ES8311` 通过 `I2S` 与 `ESP32-S3` 交换音频数据
- 当前仓库状态也支持这个判断：
  - `drivers/audio_capture/` 仍为空，说明正式音频采集驱动尚未开始
  - 现有稳定能力是 BLE HID 输出链路，适合作为本次占位验证的后半段

本次占位验证采用的最小策略：

- 不做语音识别
- 不接后端
- 不做“假语音事件”或按钮替代
- 直接走最小真实音频采集路径：
  - 初始化 `ES8311` 与 `I2S`
  - 读取短帧 PCM 数据
  - 用本地能量阈值或峰值阈值判断“检测到明显音频活动”
  - 一旦满足阈值条件，就向现有 BLE HID 链路注入固定测试字符串 `voice ok`

选择这条路径的原因：

- 当前任务目标是“捕获语音输入然后输出到 Windows”，所以不能退化成纯脚本或按钮触发
- 当前没有看到比 `ES8311 + I2S` 更直接、更可信的板级音频活动检测通路
- 先做最小 PCM 采集和阈值触发，最接近后续真实语音链路
- 这条路径完成后，后续无论接云端 ASR 还是本地 ASR，都只需要替换“固定字符串来源”，不用推翻 BLE 输出链路

为什么当前不直接上后端或语音识别：

- 后端协议和联调当前不在本方案范围内
- 当前目标是验证设备侧“音频输入存在”能否带动整机交互闭环
- 语音识别会引入额外变量，不利于当前 bring-up 阶段定位问题

与当前仓库边界规则的一致性：

- `ES8311`、`I2S`、GPIO、`ESP-IDF` 驱动细节应留在 `ports/esp32/`
- 语义化音频采集接口应放在 `drivers/audio_capture/`
- 固定字符串仍复用现有 `components/hid_keyboard/` 与 `ports/esp32/ble_hid/`，不把音频验证逻辑扩散到无关上层

验收方式：

- 文档中明确写出当前音频输入硬件路径判断
- 文档中明确写出本次占位验证采用的最小策略
- 文档中明确说明为什么当前不直接上后端或语音识别
