# BLE 键盘产品化方案

## 目标

把当前已经能工作的 BLE HID 键盘 demo，推进到“更像产品能力而不是单纯验证链路”的状态。

## 问题

当前 BLE HID 链路已经完成了字符注入验证，但仍然偏 seed 工程：

- 配对、绑定、重连策略还没有产品化定义
- 电量上报还没有纳入
- 主机输出状态处理还没有产品化
- 缺少对连接体验的统一验收标准

## 范围

- BLE 设备命名与身份信息
- 配对、绑定、重连行为
- 电量上报
- 主机输出状态处理，例如键盘 LED/控制事件
- 连接状态日志与基本诊断

## 不在本次范围内

- `2.4G dongle`
- Wi‑Fi 传输
- 复杂低功耗策略
- 完整量产认证流程

## 前提与依赖

- 当前 BLE HID 基础验证链路已完成
- 当前开发板具备电池电量检测相关硬件预留
- 当前仍以 `ESP32-S3` 平台 bring-up 为主

## 步骤

### 第一步：确认 BLE 产品化最小能力边界

状态：`pending`

工作内容：

- 明确 `v1` 必须收掉的 BLE 产品化能力
- 在“必须项”和“可延后项”之间做切分

验收方式：

- 文档中明确列出 `v1` 必须项与可延后项

人工检查点：

- 人确认 `v1` BLE 产品化边界后，AI 才进入第二步

### 第二步：固化连接与身份策略

状态：`pending`

工作内容：

- 明确设备命名、配对、绑定、重连和连接状态机

验收方式：

- 文档中明确写出连接策略与验收行为

人工检查点：

- 人确认连接策略可接受后，AI 才进入第三步

### 第三步：补齐电量与主机状态处理方案

状态：`pending`

工作内容：

- 明确电量上报方式
- 明确主机输出状态如何处理和记录

验收方式：

- 文档中明确写出电量上报和主机状态处理方案

人工检查点：

- 人确认产品化范围完整后，AI 才进入实现

## 当前阻塞项

- 需要先明确 `v1` 的 BLE 产品化边界

## 备注

- 该方案主要收的是“连接体验和产品行为”
- 不替代已完成的 BLE HID 输入验证文档
