# 实体按键输入方案

## 目标

为蓝牙语音键盘建立正式的实体按键输入链路，使输入不再依赖脚本注入，而是来自真实按键硬件。

## 问题

当前仓库里：

- `drivers/key_input/` 仍为空
- 当前已完成链路是“脚本输入 -> BLE HID 输出”
- 还没有真实按键扫描、去抖、键值映射和 HID 上报路径

## 范围

- 按键硬件输入来源确认
- 按键扫描抽象
- 去抖与重复键策略
- 键值到 HID 的映射规则
- 与现有 BLE HID 输出链路的集成

## 不在本次范围内

- 完整量产键盘矩阵原理图设计
- 键盘手感与结构设计
- 热插拔、灯效、宏功能

## 前提与依赖

- 当前开发板原理图只明确看到少量按键和 `KEY1~KEY4`
- 当前没有完整量产键盘矩阵原理图进入仓库
- 未来正式矩阵方案可能依赖专用键盘 PCB，而不是当前 `ESP32-S3` 开发板

## 步骤

### 第一步：确认当前阶段的真实按键输入来源

状态：`pending`

工作内容：

- 判断当前开发板上可用于输入验证的实体按键资源
- 判断当前是否具备完整矩阵验证条件

验收方式：

- 文档中明确当前板子能验证哪些真实按键输入
- 文档中明确哪些内容必须等正式键盘 PCB

人工检查点：

- 人确认当前按键输入验证边界后，AI 才进入第二步

### 第二步：定义 `drivers/key_input/` 抽象边界

状态：`pending`

工作内容：

- 明确键输入驱动层与 HID 层的边界
- 定义事件模型，例如按下、释放、长按、重复

验收方式：

- 文档中明确驱动边界与事件模型

人工检查点：

- 人确认驱动边界可接受后，AI 才进入第三步

### 第三步：定义验证路径

状态：`pending`

工作内容：

- 定义当前开发板的最小验证方式
- 定义未来正式键盘 PCB 的扩展方式

验收方式：

- 文档中明确当前验证方式与未来扩展方式

人工检查点：

- 人确认实体按键输入方案可接受后，AI 才进入实现
