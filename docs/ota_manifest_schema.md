# OTA Manifest Schema

Version: 2

Generated by `tools/package_ota_firmware.ps1`, validated by `tools/check_ota_manifest.ps1`, and regression-tested by `tools/test_ota_manifest_validation.ps1`.

The generated zip is a firmware release bundle, not an OTA-only archive. Its
top level contains the BLE OTA files, and successful factory packaging also
adds the wired flashing package under `factory/`:

```text
ota_manifest.json
firmware_ota.bin
factory/
  listener-factory-.../
    manifest.json
    FLASHING.md
    bootloader.bin
    partition-table.bin
    voice-keyboard-firmware.bin
```

Desktop tools should reuse the same bundle by reading `ota_manifest.json` and
`firmware_ota.bin` for BLE OTA, and `factory/*/manifest.json` plus its artifacts
for wired factory flashing or bootloader repair.

## Top-level Fields

| Field | Required | Type | Description |
|-------|----------|------|-------------|
| `schema_version` | yes | int | Always `2` |
| `created_at_utc` | yes | string | ISO 8601 UTC timestamp |
| `channel` | yes | string | `stable` or `development` |
| `firmware` | yes | object | Firmware binary metadata |
| `requirements` | yes | object | Target compatibility constraints |
| `ble_identity` | yes | object | BLE service/characteristic identifiers |
| `rollback` | yes | object | Rollback capability description |
| `recovery` | yes | object | Recovery instructions |

## firmware

| Field | Required | Type | Description |
|-------|----------|------|-------------|
| `project` | yes | string | Project name (`voice-keyboard-firmware`) |
| `version` | yes | string | Plain release semver such as `1.0.0` |
| `git_commit` | yes | string | Full git commit SHA |
| `git_dirty` | yes | bool | Whether tree had uncommitted changes |
| `target` | yes | string | Build target (`esp32s3`) |
| `file` | yes | string | OTA binary filename (`firmware_ota.bin`) |
| `size_bytes` | yes | int | File size in bytes |
| `sha256` | yes | string | Lowercase hex SHA256 of the binary |

## requirements

| Field | Required | Type | Description |
|-------|----------|------|-------------|
| `hardware_revision` | yes | string | Target hardware revision (`keyboard-v2-n16r8`) |
| `protocol_version` | yes | int | BLE protocol version number |
| `min_desktop_version` | yes | string | Minimum Listener-Type desktop version required |

## ble_identity

Copied from factory manifest. Contains `name`, `appearance`, service UUIDs, and DIS fields.

## rollback

| Field | Required | Type | Description |
|-------|----------|------|-------------|
| `supported` | yes | bool | Always `true` for ESP-IDF bootloader rollback |
| `method` | yes | string | `esp_idf_bootloader_rollback` |
| `instructions` | yes | string | Human-readable rollback behavior |

## recovery

| Field | Required | Type | Description |
|-------|----------|------|-------------|
| `factory_reflash` | yes | string | How to restore factory image |
| `serial_commands` | yes | string | Diagnostic serial commands |

The validator rejects schema version 2 manifests that omit any required field in
the tables above, including `created_at_utc`, `ble_identity`,
`rollback.method`, `rollback.instructions`, `recovery.factory_reflash`, and
`recovery.serial_commands`.

## Channel Rules

- **stable**: Requires clean git tree, clean release version string, and a complete nested factory package in the release bundle. For production releases.
- **development**: Allows dirty tree and OTA-only package output when factory artifact generation fails. For local development builds only.

## Versioning

The `firmware.version` field is resolved in order:
1. `project_description.json` `project_version` (set by build system)
2. repository `VERSION`
3. `git describe --tags --always --dirty` as a legacy fallback
4. Fallback: `1.0.0`

The desktop app should compare `requirements.min_desktop_version` against its own version before offering the update, and verify `requirements.hardware_revision` matches the connected device.
