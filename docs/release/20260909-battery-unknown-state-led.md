# V2.2 电量未知态与充电灯修复记录

记录日期：2026-09-09（Asia/Shanghai）

这是一份**已记录、暂不进入 1.0.5 稳定包**的修复笔记。由于当前候选版本的整体录音体验不稳定，回归验证使用已确认可用的 1.0.5 基线；下面的改动留作下一轮候选版本的独立补丁。

## 根因

V2.2 的 `BAT_IN` 位于受 `PWR_HOLD` 控制的电池电源域之后。关电或低功耗阶段，ADC 可能仍然成功返回 `0 V`，但这代表“当前不可测”，不是“电池 0%”。如果把它直接转换成电量百分比，会造成：

- BLE HID 电量被刷新成 0%；
- OTA/设置页误判为低电量；
- 充电时白色呼吸灯从上次真实电量跳到错误的 0%/未知底值；
- 电量灯呼吸节奏和亮度看起来像状态抖动。

## 已验证的补丁内容

以下修改已经在工作树中实现并通过过一次 ESP-IDF build，但随本次回归会从代码中撤下，只保留本记录：

1. `components/battery_monitor/battery_monitor.c`
   - 只有 ADC 成功且电池电压达到绝对有效下限时才设置 `valid=1`；
   - 无效样本使用协议的 `DENZIC_BATTERY_V1_INVALID_LEVEL`，不再制造新鲜的 0%。
2. `ports/esp32/ble_hid/ble_hid.c`
   - 无效样本不覆盖 HID characteristic；
   - 保留最近一次有效电量，并通过 OTA/诊断通道标记 `battery_valid=0`。
3. `components/status_led/status_led.c`
   - 无效样本不清空充电呼吸的显示缓存；
   - 恢复有效采样后再更新电量对应的呼吸底值，避免每次切换电源域都跳变。
4. Listener Type 主机端
   - BLE 标准电量的 `0/default` 仅作为未知值，不显示为真实 0%；
   - OTA 低电量门禁把 0 当作 unknown；
   - 设置页显示“电量未知/等待有效采样”，不把未知电量画成 0%。
