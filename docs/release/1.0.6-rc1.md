# Listener Firmware 1.0.6 RC1

Listener keeps listening across hidden recording windows and preserves a
confirmed recording when Type takes it over. This firmware candidate pairs
with [Type RC1](https://github.com/Listener-ai-Macau/Listener-Type/releases/tag/v1.0.6-rc1)
for desktop speech input.

Tag: `v1.0.6-rc1`. This is a **prerelease** and does not replace the public
1.0.5 stable release. Hardware: Listener keyboard-v2 / ESP32-S3 N16R8.

## Update

- Download `listener-ota-1.0.6-rc1-20261011-230051.zip` and verify it with `SHA256SUMS.txt`.
- Use Type RC1's firmware update control and select this OTA ZIP. Normal OTA
  keeps device settings and Bluetooth pairing and uses the existing rollback
  mechanism.
- The ZIP also includes a factory recovery directory and its flashing guide.
  Factory recovery is for engineering/recovery; ordinary customers use OTA.
- The OTA manifest uses the development channel for this RC and requires
  desktop version `1.0.6-rc1` or newer. No stable updater manifest was replaced.

## Changes since the public 1.0.5 firmware

- Preserve monitoring and audio continuity across recording/transfer windows.
- A successful normal hidden-window rotation no longer enters the recovery
  wait intended for a failed stop.
- A confirmed Type wake can take over an ambient start that is queued but has
  not actually started. Explicit controls and voiceprint enrollment retain
  their ownership protections.
- Carry source/segment coordinates through takeover and avoid substituting
  stale audio for a requested continuation.
- Preserve transport drain and backpressure handling, power-source filtering
  and low-power wake behavior from the current repaired device baseline.
- Track `VERSION` as a build configuration dependency. OTA/factory packaging
  rejects an obsolete build version rather than labeling it as a new release.
- Pin publicly available platform sources with identical consumed embedded C
  logic so another developer can obtain the release dependency.

## Evidence and remaining limits

The functional C baseline is the firmware installed and observed on the repair
device as `1.0.5 / 70cf774051226c5f`. RC1 retains that functionality, changes the
release identity, and fixes version/build packaging. The new image descriptor,
checksum, manifest and package payload were checked. This RC image has not yet
been flashed on that device; the previous baseline's physical evidence does
not constitute new RC OTA installation evidence.

Automatic wake under strong speech interference is not fully reliable. This
firmware does not itself transcribe or guarantee removal of other speakers;
recognition, local speaker decisions and text insertion are performed by Type.
The Type release notes describe remaining false wakes and foreign-text limits.
