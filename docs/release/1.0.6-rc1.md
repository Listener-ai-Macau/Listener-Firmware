## Changes / 本次累计变化

- Return the real execution result for all four canonical USB Type-recovery commands at the shared queue-consumer boundary. The stable rename path previously ran successfully but appeared to time out, causing redundant BLE writes and recovery retries.
- Retain the last actor-executed ENSURE request/result/segment/ownership after STOP or ABORT for diagnosing intermittent capture handoff. This does not change silence timing or grant recording ownership.
- Retain the installed capture-origin/ownership ordering fixes and pre-roll cooperative waits. The full original pre-roll remains; waits still genuinely block and preserve the watchdog/backpressure protections.
- Retain DLE command-completion ownership and later effective-length downgrade handling. OTA erase/reorder/wire support remains; no raw-throughput target is claimed achieved.
- A single firmware ZIP includes the factory manifest/bootloader/partition table/app for USB, and the OTA manifest/app for Bluetooth. Both app binaries have the same SHA-256.

## Evidence and remaining issues / 验证范围与未解决问题

- A physical rename after the USB execution-result repair recovered audio notification readiness in **6.537 s** from the write plan; the saved earlier failure took **35.994 s**. The user confirmed it felt much faster. These are two observed runs, not a universal timing guarantee.
- Type build36 is installed and its executable matches the released MSI. The completion-notice decision was checked against the saved rename reason, duplicate callbacks and excluded internal refresh paths. The visible notice still awaits a natural real rename; no new speech acceptance is claimed.
- **Intermittent wake/capture handoff can still end early.** Two original failures are preserved; the same older binaries also had a successful sustained session. Firmware now retains the actual last ENSURE execution result for diagnosis. This is observability, not proof of a complete fix.
- Strong external speech may enter the transcript or affect wake/automatic closing. Strict speaker isolation is not claimed. New local-model experiments and additional paid cloud services are excluded.
- Some native editor/clipboard handoffs remain under investigation. The unvalidated Document-role candidate and 215-byte OTA experiment are **not included** in this app build.
- No claim of 160 KB/s raw Bluetooth throughput is made. Default OTA transfer is raw/uncompressed. ZIP storage compression is only packaging, not the transfer optimization metric.
- MSI/EXE remain unsigned. Supported provider credentials are required; a hosted subscription backend is not included. The optional recovery model is downloaded on demand and can add roughly 890 MB to local storage.
