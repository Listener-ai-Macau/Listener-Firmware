# Listener Firmware 1.0.6 RC1 — inactive-capture cleanup

Release candidate refreshed on **16 October 2026**, paired with
[Listener Type RC1 build 20](https://github.com/Listener-ai-Macau/Listener-Type/releases/tag/v1.0.6-rc1).
Hardware: Listener keyboard-v2 / ESP32-S3 N16R8. This remains a prerelease;

## Install

- Download `listener-ota-1.0.6-rc1-20261015-135227.zip` and verify `SHA256SUMS.txt`.
- Select the OTA ZIP in Type's firmware updater. Normal OTA preserves settings
  and pairing and retains the existing rollback mechanism.
- A factory recovery directory and flashing instructions are included for
  engineering/recovery. The manifest requires desktop 1.0.6-rc1 or newer.
- Running firmware: **1.0.6-rc1 / `9d92421e915196b4`**.

## Fix in this build

A stop or cancel can race the capture layer finishing. When the interface
returned an error but capture was already inactive, the controller set itself
to Idle before completing its recording-light/output cleanup. The polling
path then skipped that Idle session. Synchronous cancellation had another
partial cleanup path.

Those branches now use the existing SESSION_INACTIVE terminal owner, including
cancel/continuation bookkeeping, diagnostics, host speech protection, recording
output and LEDs. Power blockers are released after observable outputs are
quiescent. A still-active capture is kept active after a failed operation. Old
error logs are emitted before terminal cleanup can start a successor session.
This changes no silence timeout, voice thresholds or recognition policy.

## Retained behavior

Hidden transport windows preserve acoustic continuity; Type can take over a
confirmed or pending automatic recording without toggling it off. Segment/source
coordinates, explicit control/enrollment ownership, drain/backpressure handling,
power-source filtering and low-power wake behavior are retained.

## Evidence and limits

The original production stop function reproduced the stale recording-light
state with an inactive capture and INVALID_STATE. The repaired production
controller and reducer passed targeted stop/cancel failure, active-capture
protection, synchronous/asynchronous cancel, ensure bookkeeping and power-release
ordering checks. The firmware was built from source commit
`f11598aba848cc6ef3109592de7e193af3e9e17e` and installed on the repair device with settings and
otadata preserved. Both serial diagnostics and the installed Type read back
`9d92421e915196b4`. The desktop notify subscription was restored after the
engineering wired update.

These checks establish the code repair and running-image identity, not a new
physical-light or full hardware acceptance run. Strong interference, false
wakes, foreign words and background-dependent closing remain limited by Type's
recognition and speaker evidence; this firmware does not isolate speakers.
