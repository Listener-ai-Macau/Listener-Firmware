## Scope

Step 1.1 replaces the automatic long-idle Deep Sleep path with a firmware-controlled hardware shutdown path that releases `PWR_HOLD/GPIO11` through the board abstraction. It also updates power diagnostics, startup reset diagnostics, board status output, BLE shutdown preparation, static verification scripts, feature docs, and firmware feature metadata.

This step does not claim real hardware power-off success. Real `PWR_HOLD` HIGH boot evidence, automatic complete power-off, current/serial/BLE disappearance, and short-press cold-boot recovery remain the hardware gate for step 1.2.

## Implementation Evidence

- Automatic long-idle shutdown now enters `POWER_MANAGER_STATE_HARDWARE_SHUTDOWN` and calls `board_set_power_hold_enabled(false)` instead of `esp_deep_sleep_start()`.
- Shutdown entry logs serial and `diag_log` evidence before releasing `PWR_HOLD/GPIO11`, and prepares LED, audio idle power save, system health low-power mode, and BLE disconnect.
- Deep Sleep wake policy code, RTC wake state, wake-source status output, and `~POWER:SLEEP` command handling were removed or replaced with reset/shutdown diagnostics and `~POWER:SHUTDOWN`.
- Board diagnostics now expose `pwr_hold_gpio`, `pwr_hold_level`, `pwr_hold_configured`, and the V2 GPIO11 latch policy.
- USB, charging, charge-full, and external-power blockers continue to prevent automatic hardware shutdown while preserving manual shutdown.
