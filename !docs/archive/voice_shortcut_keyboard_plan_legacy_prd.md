## 一句话定义

`v1` 是一个 `BLE only` 的蓝牙语音快捷键键盘：设备端提供 `4` 个可编程实体键、`1` 个旋钮、语音录音触发和麦克风采集；`Windows` 轻量主机端负责接收音频、对接语音识别 / agent 入口，并完成文本或动作输出。

它不是完整打字键盘，也不是一开始就覆盖跨平台、离线识别、Wi-Fi 传输或完整 agent 产品的“大而全”方案。

## 产品目标

- 让用户可以用一个小型蓝牙输入设备完成快捷键、系统动作和语音输入触发。
- 把设备端语音采集稳定上传到 `Windows` 主机端，作为后续 ASR / agent 能力的入口。
- 保留标准 `BLE HID` 输入能力作为快捷键、调试链路和 fallback。
- 建立产品级连接、恢复、日志和自动化验收口径，避免只靠人工蓝牙界面判断“好像连上了”。

## 非目标

- 不做完整键盘矩阵。
- 不在 `v1` 做完整自研输入法。
- 不在设备端跑离线语音识别模型。
- 不在 `v1` 做 `Wi-Fi` 音频传输或 `2.4G dongle`。
- 不在首轮要求完整 OTA、极致低功耗或完整量产认证闭环。
- 不把 `Windows` 主机端做成重型跨平台大 app。

## 用户与场景

### 目标用户

- 需要高频语音输入、快捷操作、agent 唤醒的桌面用户。
- 需要一个比完整键盘更小、更专注的语音快捷控制器的用户。

### 核心场景

- 用户按下语音键，设备开始录音，并把音频持续上传到 `Windows` 主机端。
- 用户再次按下语音键，设备结束本次录音会话，主机端拿到完整会话。
- 用户按下其他实体键，触发预设快捷键、系统键或主机端动作。
- 用户旋转旋钮，完成音量、滚动、候选切换等连续型操作。
- 设备 reset、空闲、主机蓝牙异常或接收进程重启后，用户仍能恢复继续使用。

## 产品范围

### `v1` 必须包含

- `BLE HID` 标准键盘能力。
- `4` 个可编程实体键。
- `1` 个旋钮。
- 默认快捷键 / 系统键 / 语音触发映射。
- 设备端麦克风采集。
- `16kHz / mono / 16-bit PCM` 音频基线。
- 基于会话的音频协议：`session_start -> audio_data -> session_stop / session_cancel`。
- `BLE notify` 音频上传与主机端重组。
- `Windows` 轻量主机端的最小接收与语音输入 / agent 入口。
- 连接、录音、上传、恢复相关日志。
- 脚本化稳定性回归矩阵。

### `v1` 可延后

- 图形化键位配置软件。
- 跨平台主机端。
- 真实电量计完整接入。
- 更复杂的候选词 / IME 深度控制。
- Wi-Fi 音频传输。
- 长时间全天候 soak 量产标准。

## 方案分层

### 设备端职责

- 暴露稳定的 `BLE HID` 键盘能力。
- 消费 `4` 键 + `1` 旋钮输入事件。
- 管理语音键开始 / 停止 / 取消录音状态机。
- 采集麦克风音频。
- 通过 `BLE notify` 按会话上传音频。
- 输出关键状态日志，支持脚本化排障。

### Windows 主机端职责

- 常驻或按需接收设备上传的音频会话。
- 按 `session_id + packet_sequence` 重组音频。
- 对接流式识别、文本输出或 agent 唤醒入口。
- 提供最小状态提示、日志和恢复能力。
- 不成为基础快捷键 / HID fallback 的唯一前提。

### 后端职责

- 负责正式 ASR / agent 能力。
- 冻结设备到主机 / 后端的会话语义、错误码、超时和重试规则。
- 给出示例请求、响应、失败处理和版本兼容约束。

## 功能需求

### FR1：BLE 键盘产品化

必须具备：

- 设备命名与身份信息稳定。
- 配对、bond、重连行为清晰。
- reset 后可自动恢复可用连接。
- 空闲后再次使用仍可恢复。
- 主机蓝牙服务异常后有明确恢复路径。
- Windows 假连接态有检测和恢复方式。
- 连接状态、加密状态、订阅状态可观测。

验收口径：

- reset 回连、空闲恢复、异常恢复均有脚本或半自动脚本覆盖。
- 不能只依赖 Windows 蓝牙 UI 的“已连接”状态。

### FR2：4 键 + 1 旋钮输入

必须具备：

- 固件能区分 `4` 个实体键。
- 固件能稳定读取 `1` 个旋钮方向 / 步进事件。
- 输入事件可映射到 `BLE HID` 或主机端动作。
- 默认映射不依赖完整键盘矩阵。

验收口径：

- 日志能明确标出输入来源。
- 至少一组默认映射能在 `Windows` 上稳定复测。

### FR3：默认快捷键 / 系统键 / 语音键映射

建议默认配置：

- `KEY1`：语音录音开始 / 停止。
- `KEY2`：主机端语音输入或 agent 唤醒。
- `KEY3`：默认系统动作或常用快捷键。
- `KEY4`：默认系统动作或常用快捷键。
- `ENCODER`：音量、滚动或候选切换。

验收口径：

- 默认映射有清晰文档。
- 每个默认动作都有可复测路径。
- 后续自定义模型不被当前默认映射锁死。

### FR4：设备端音频采集与上传

必须具备：

- 音频格式：`16kHz / mono / 16-bit PCM little-endian`。
- 基础帧：`20ms = 320 samples = 640 bytes`。
- 上传模型：流式连续上传，不是整段录完后一次性发送。
- 会话模型：`session_start -> audio_data -> session_stop / session_cancel`。
- 主机端缺包补静音，优先产出完整时长 `wav`。

验收口径：

- 单轮录音能稳定生成可分析 `wav`。
- 多轮、恢复、重连、取消、异常结束纳入产品级矩阵。

### FR5：Windows 轻量语音输入 / agent app

必须具备：

- 能接收设备上传的音频会话。
- 能把设备动作接到语音输入或 agent 唤醒入口。
- 能保留必要日志与错误状态。
- 首版 UI 可以很轻，但进程形态、启动方式、日志位置必须明确。

验收口径：

- 在 `Windows` 上完成一次“设备触发 -> 音频接收 -> 识别入口 / agent 入口被拉起”的闭环。

### FR6：日志、自检与恢复

必须具备：

- BLE 连接、加密、订阅、MTU、notify 状态日志。
- 录音开始、停止、取消日志。
- 上传开始、结束、跳过、失败日志。
- 主机侧恢复脚本或恢复入口。
- 版本、自检、故障定位字段。

验收口径：

- 不依赖 `idf.py monitor` 交互输入，命令行脚本可完成关键验证。
- 所有脚本必须有明确超时预算，超过预算直接退出并报告 timeout 原因。

## 非功能要求

- `Windows first`，不是跨平台 first。
- `BLE only`，Wi-Fi 暂不进入 `v1`。
- `ESP32-S3` 用于当前 bring-up；后续产品芯片可按 [product_solutions.md](../product_solutions.md) 切换。
- 代码继续保持 `ESP32 now, STM32 later` 边界：
  - `main/` 保持薄。
  - 平台绑定放在 `ports/esp32/`。
  - 可复用产品逻辑放在 `components/` 和 `protocols/`。
- 主机端与后端协议冻结前，不把临时字段写死成不可演进接口。

## 当前已经完成

- `BLE HID` 逐键输出链路已稳定可用。
- 固件已切到 `NimBLE`，bond / 自动回连主路径已经打通。
- reset 后自动回连、主机侧恢复脚本、端到端输入验证脚本已经具备。
- `BLE HID` ASCII / 快捷键输出保留为 fallback，不再作为中文语音输入主线。
- 设备端音频采集、录音控制与 `BLE notify` 上传单轮链路已经可用。
- `KEY1` 录音控制和 USB 串口控制命令链路已经具备。
- 主机端音频重组、`wav` 落盘和产品使用面矩阵入口已经具备。
- 面向后端的音频会话契约已开始沉淀到 [voice_input_backend_contract.md](../features/voice_input_backend_contract.md)。

## 当前未完成

- `4` 键 + `1` 旋钮的正式硬件输入方案还未落成。
- 默认键位、旋钮行为和可配置模型还未冻结。
- `Windows` 轻量语音输入 / agent app 还未形成实现闭环。
- BLE 音频多轮、恢复、重连等产品级稳定性仍在收敛。
- 后端正式协议、错误码、超时和重试规则还未最终冻结。
- Wi-Fi 传输暂不进入 `v1`，未来如果切换传输层，需要复用会话协议语义而不是重写产品语义。

## 主要风险

- `BLE notify` 音频上传在 Windows 恢复 / 重连后仍可能出现首轮不稳定。
- 当前 bring-up 平台是 `ESP32-S3`，后续产品芯片如果切到 `ESP32-C3`，需要验证平台层差异。
- 主机端 app 边界如果不尽快冻结，设备端协议容易反复变动。
- 后端契约如果不冻结，音频结束语义、取消语义、错误恢复会影响整条体验。
