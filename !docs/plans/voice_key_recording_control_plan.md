# 语音键触发控制方案

## 目标

建立“语音键按下开始、释放结束、异常可取消”的输入控制链路，为后续音频采集、上传和文本返回提供统一入口。

## 问题

当前仓库还没有语音输入状态机：

- 没有定义语音键事件
- 没有定义录音开始、保持、结束、取消逻辑
- 没有把语音键与音频链路和 HID 输出链路接起来

## 范围

- 语音键事件模型
- 录音控制状态机
- 与音频采集或占位链路的连接
- 与后续上传和文本返回链路的接口边界

## 不在本次范围内

- 语音识别算法
- 后端协议细节
- 复杂 UI 动效

## 前提与依赖

- 需要有一个真实按键来源，或至少有一个可替代的实体触发键
- 需要与 `audio_input_placeholder_plan` 或 `audio_capture_bringup_plan` 对接

## 步骤

### 第一步：定义语音键状态机

状态：`pending`

工作内容：

- 定义状态，例如空闲、录音中、结束中、取消中
- 定义状态转换条件

验收方式：

- 文档中明确列出状态、事件和转换关系

人工检查点：

- 人确认状态机定义后，AI 才进入第二步

### 第二步：定义与音频链路的接口

状态：`pending`

工作内容：

- 明确语音键如何启动和停止音频链路
- 明确异常和超时如何处理

验收方式：

- 文档中明确接口和异常处理方式

人工检查点：

- 人确认接口边界可接受后，AI 才进入第三步

### 第三步：定义验证方式

状态：`pending`

工作内容：

- 明确当前板子上的验证方式
- 明确日志和主机侧可观察结果

验收方式：

- 文档中明确验证方式和预期结果

人工检查点：

- 人确认语音键控制方案可接受后，AI 才进入实现

## 当前阻塞项

- 依赖实体键输入来源和音频链路入口定义

## 备注

- 该方案是语音输入全链路的控制入口
- 后续音频采集、上传和文本注入都应复用这里定义的状态机边界
